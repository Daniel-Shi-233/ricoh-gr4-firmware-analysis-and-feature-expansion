# GR IV 研究日志

按本次研究过程整理。结论来自固件静态分析、USB 只读查询，以及用户在一台自有 GR IV 上完成的实机测试。没有将修改后的固件用于升级。

## 1. 固件更新包和版本字段

- 从官方 GR IV 1.11 固件包取得 `fwdc248b.bin` 样本，检查头部型号字段与版本字段。四个字节显示为 `1.11.10.7`，公开的主次版本是 `1.11`。
- 解压帧格式后检索到 CPU、SRIC、DSP 的四段版本日志，以及“版本比当前版本旧”的提示。由此判断固件包有内部细版本，升级预检存在版本比较。
- 对完整文件按小端 32 位字求和，模 `2^32` 为零。仅凭此算法无法断定固件没有密码学签名检查；也无法从字符串完全还原版本比较规则。
- 理光说明 GR IV 固件不支持降级。因此将自制包的内部版本不断提高可能导致旧的正式版本无法覆盖，不能假定未来固件一定可恢复。项目没有测试或发布任何改版固件。

## 2. USB 和 MTP

- 连接 GR IV 后读取到 USB ID `0x25FB:0x2123` 和单一 PTP/MTP 接口。macOS 的相机进程 `ptpcamerad` 会持有接口；退出占用进程后只读查询可以短暂进行。
- 在菜单的“影像显示”模式下查询到照片存储；在“许可证显示”模式下查询到只读许可证存储。切换模式没有改变 USB 接口类型。
- 两种模式返回标准 MTP 读取操作，但没有文件上传所需的 `SendObjectInfo` / `SendObject`。Android 文件传输应用无法借这两个模式将系统文件写入相机。
- 结论：USB 查询解释了为什么普通 Android 文件传输或访达无法直接浏览系统资源盘。后续成功的写入实验走的是 SD 卡启动脚本路径，不是 USB。

## 3. 工厂菜单入口

- 根据固件中的工厂模式判断逻辑，推导出 SD 卡根目录需要两个机型相关文件，其中 `DEVELOP.MOD` 长 10 字节。空文件测试没有触发菜单。
- 把文件内容修正为固件中匹配的一组 10 字节后，普通电源键开机仍进入普通模式。
- 用户发现需要在开机时按住 MENU，随后成功进入工厂菜单。照片确认首屏为 `FW Setting1`，包括 `Camera Mode`、`Script`、`Key Emulate`、`Serial Input`、`Store Debug Log`、`HDMI Format Priority` 和 `Thermal ShutDown`。
- 通过固件的页面名表还原了 `FW Setting2` 和其他页面名称。菜单项名不等于完整功能说明；没有验证的项目不应按名称猜测后操作。

## 4. 启动脚本与存储盘写入

- 固件包含 `C:\script\startup.ttl` 等脚本路径以及 `filecopy`、`filesearch` 等文件命令。菜单启用 `Script` 后，放入 SD 卡的 `script/startup.ttl` 能在相机启动过程中执行。
- 第一阶段把资源盘上的原关机图复制到 SD 卡。读回原图与固件样本中的图片字节完全一致，确认脚本可读取资源盘并写卡。
- 第二阶段用小文本做可逆探针：将 SD 卡上的测试文件复制到资源盘根目录，再复制回 SD 卡验证内容。成功后移除临时测试文件。该结果确认这台相机上的 `A:` 根目录可写。
- 然后对 `A:\Resource\Jpeg\GoodBye.jpg` 做备份、覆盖和回读。第一次尝试的替换 JPEG 比原图短；实机回读发现旧文件尾部仍残留，因此完整 SHA-256 不匹配。画面虽然显示了新图，这次回读暴露出 `filecopy` 不截断旧文件。
- 将 JPEG 加入不改变解码像素的合法 COM 段，补到原文件精确长度后重新写入。相机回读 SHA-256 与待写文件相同，用户确认关机画面正确，取出 SD 卡后仍显示，确认资源写入已持久化。
- 之后测试了尺寸更大的第二版，先在目标目录测试文件扩容并读回成功，再部署并核对完整哈希。第三版也完成写入及读回，最终画面正常。
- 移除启动脚本和临时图像/读回件后，用户将 `Script` 设回 Disable，正常开关机确认最终画面仍显示。原始关机图备份和工厂菜单入口文件保留在用户自己的 SD 卡/本地工作区，没有放入本仓库。

## 5. 最终结论与边界

1. 关机图资源位于 `A:\Resource\Jpeg\GoodBye.jpg`，该文件路径由固件资源和引用确认。
2. 本次成功路径依赖工厂菜单启用 Script、SD 卡启动脚本及固件自带文件复制命令；USB/MTP 没有参与写入。
3. 必须先备份、再写入并从相机读回核对。覆盖较短文件可能留下旧尾部；本次用整文件长度匹配或先验证扩容的方式规避。
4. 在写入目标前无法从这些实验推出所有资源路径都可写，也无法推出工厂菜单每个项目的作用。
5. 所有实机写入测试均在用户自己操作的设备上完成。仓库不含固件镜像、设备读回数据或品牌图稿；为便于复现，现包含生成入口文件的工具和备份/写入 TTL 示例。
